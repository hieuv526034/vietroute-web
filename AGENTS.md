# VietRoute — chỉ dẫn dùng chung cho AI

## Bắt đầu mỗi phiên làm việc

1. Đọc file này, [AI và bàn giao](docs/06-ai-va-ban-giao/AI_VA_BAN_GIAO.md), [tiến độ](docs/05-ke-hoach/TIEN_DO_VA_KE_HOACH_NHOM.md) và [phân công](docs/05-ke-hoach/PHAN_CONG.md). Theo [mục lục](docs/README.md) để đọc thêm đúng chuyên đề trước khi sửa phần đó.
2. Kiểm `git status --short --branch`, commit gần nhất và code/PR liên quan. Nêu ngắn gọn mã việc, phần đã có/còn thiếu, nhánh/người thực hiện và cách kiểm; tiếp tục công việc đã được người dùng cho phép. Giữ nguyên thay đổi có sẵn của người khác.
3. Quy tắc repo nằm ở đây; trạng thái/bằng chứng nằm ở tiến độ/PR; quyết định dài hạn nằm trong tài liệu chuyên đề. File dành riêng cho từng công cụ chỉ dẫn về nguồn này, không sao chép một bộ quy tắc khác. Không coi chat, memory cá nhân hoặc kế hoạch là bằng chứng chức năng đã hoàn thành.
4. Chốt source bằng formatter đã khóa: `npm ci`, `npm run format`, `npm run format:check`; chạy `npm run check:rules`, `npm run check:docs` và kiểm thử phù hợp thay đổi. Stage file mới trước kiểm repository vì checker chỉ đọc file được Git theo dõi. Không tự sửa rule/formatter để làm check xanh.
5. Trước khi dừng, cập nhật tài liệu/PR theo mẫu bàn giao trong quy trình AI: đã làm, còn dở, quyết định và lý do, test đã chạy/chưa chạy, giới hạn và bước tiếp theo. Không ghi secret hoặc quyết định chỉ trong memory cá nhân. Chỉ ghi Đã có trên main khi có merge thật.

Docs: gốc `docs/` chỉ giữ README với 5 bước đọc và link các cụm 01–06/99. Đặt chuyên đề vào cụm phù hợp, ưu tiên sửa/gộp nội dung đang có; không thêm file Markdown rời hoặc bản sao quy tắc/trạng thái. Khi chuyển/gộp tài liệu phải cập nhật mọi link/prompt/checker; chạy check:docs để giữ cấu trúc này.

## Project conventions

- Stack: Java 17+, Spring MVC 6, Thymeleaf, PostgreSQL, WAR on Tomcat 10.1. AUTHDB03: auth CRUD dùng Spring Data JPA/Hibernate theo xác nhận 01/11/2026; BUSINESSDB01: CRUD business đơn giản cũng dùng JPA/Hibernate; JDBC dành cho batch/query phức tạp/khóa nguyên tử. Không thêm Spring Boot.
- Production database is the user's Neon PostgreSQL `neondb`. Credentials are in the root `.env` and Render environment variables. Theo yêu cầu rõ ràng 01/11/2026, được commit chính file `.env` ở gốc để chuyển máy; ngoại lệ này không cho phép ghi secret vào chat/log/docs, file khác hoặc image. Các `.env.*` khác vẫn bị ignore; WAR/Docker/test không tự đọc file này.
- PostgreSQL is supported; Oracle preparation follows DB01 in `docs/02-phat-trien/QUY_UOC_PHAT_TRIEN.md`. Use vendor adapters/migrations, preserve PostgreSQL checksums; changing URL/driver does not enable Oracle. No routine schema/seed/cleanup/test writes on production.
- Put Java tests in `src/test/java` and test fixtures in `src/test/resources`. Production Docker builds copy only `src/main` and use `-Pproduction`, which skips both test compilation and execution. Keep tests and test dependencies out of the production WAR/image.
- Dev CI checks formatting/Node/Java/docs without production images/deploy. Release CI validates Docker/PostgreSQL; Render stays on main + checksPass. Keep production path filters aligned with `render.yaml`; tests/docs alone never trigger production builds.
- Use `.env.example` for placeholders only. WAR/Tomcat and Render receive environment variables. The `local` development launcher explicitly enables the root local env file through ConfigurationEnvironment; OS/IDE values take precedence. Tests/builds never implicitly read the local file.
- Follow `docs/02-phat-trien/QUY_UOC_PHAT_TRIEN.md` and `docs/02-phat-trien/API_BASE.md`. Packages are `common`, `auth`, and `business/<module>/{controller/api,dto/request,dto/response,dto/search,entity,repo,service,initializer}`. Config classes live in responsibility subpackages of `common/config` (application/database/integration/traffic/monitoring/web); only RootConfig/WebApplicationInitializer stay at its root; do not reintroduce the old top-level config/web/identity layout.
- Add Vietnamese comments/Javadoc for flows, service methods and transaction boundaries. Every public API has `@Operation`; request/response fields have `@Schema`. Add all message keys to both vi/en bundles; use `BusinessException(ErrorCode, args)` and the shared response factory.
- Bootstrap/migrations run only at application startup when explicitly enabled, never in Maven packaging. Preserve migration checksums, advisory locks, idempotent seed and existing admin passwords. Runtime initialization for the requested admin/catalog foundation is authorized; routine verification uses isolated PostgreSQL, not production.
- Use Spring Security/Nimbus JWT and BCrypt. Never store browser access tokens in localStorage, expose password hashes in DTOs, disable cookie CSRF protection, or trust client audit/role/tenant fields. `auth` owns account credentials and authorization.
- WAR dùng root/servlet context riêng; giữ `@EnableMethodSecurity` ở cả `SecurityConfig` và `WebConfig`; auth hiện hành không có annotation action. EndpointAccess kiểm HTTP trước handler, service kiểm principal đã duyệt/nghiệp vụ/transaction, SQL kiểm scope/owner; không coi bật method security là tự bảo vệ mọi method Java. Khi sửa kiểm quyền, có regression dựng hai context như production và kiểm người thiếu quyền nhập URL trực tiếp, không chỉ kiểm menu/context gộp.

- Application schema defaults to `vietroute` inside Neon database `neondb` and is configured only by `VIETROUTE_DB_SCHEMA` (fallback `db.schema` in database.properties). Never hardcode a schema prefix in runtime DAO SQL or entity annotations. AUTH19: every borrowed connection begins a transaction before setting validated LOCAL search_path to the configured schema with pg_temp last, without public/$user fallback. BaseRepository callbacks use JdbcTransactions commit/rollback; direct journal/activity writes explicitly commit. Never switch that borrowed connection to autocommit or rely on session state across transaction-pooler backends. `@JdbcTable`/`@JdbcIndex` declare table/PK/index metadata using the configured connection schema. Keep V001–V003 byte-for-byte unchanged; LegacyMigrationSql adapts only V002/V003 in memory with raw-file checksums preserved. New migrations use the configured search_path. Changing existing schema data requires an offline rename; startup must reject an unexpected/multiple history instead of seeding a second application.
- Role là nhóm quyền duy nhất. AUTHDB03: không còn permission/action registry hoặc annotation quyền; EndpointAccess tự thu thập method + route template từ Spring MVC. DB gán User → Role → Function → Menu/API; EndpointAccess kiểm snapshot DB trước handler. Endpoint chưa gán mặc định bị từ chối, kể cả bootstrap; cờ public/self-service do WebRoutePolicy quản lý, không nhận từ DB/client.
- AUTHDB03 thay kiểm quyền VIEW/READ/CRUD cố định bằng endpoint chính xác trong DB. Không suy quyền từ tên role, HTTP verb hoặc tiền tố mã. Giữ tokenVersion/lifecycle, audit/version, ownership và scope; all_scopes phải thuộc chính role cấp endpoint đó, không union quyền từ role/scope khác.
