# Project conventions

- Stack: Java 17+, Spring MVC 6, Thymeleaf, plain JDBC, PostgreSQL, WAR on Tomcat 10.1. Do not introduce Spring Boot or an ORM without a task requiring it.
- Production database is the user's Neon PostgreSQL `neondb`. Credentials are in the ignored local `.env` and Render environment variables. Do not print, commit, or bake credentials into images.
- Use PostgreSQL SQL syntax for all new schema/DAO work. Do not run schema changes, seed data, cleanup, or write tests against production as part of routine build verification.
- Put Java tests in `src/test/java` and test fixtures in `src/test/resources`. Production Docker builds copy only `src/main` and use `-Pproduction`, which skips both test compilation and execution. Keep tests and test dependencies out of the production WAR/image.
- GitHub Actions validates the production Docker container. Render builds from `Dockerfile` and deploys `main` only after CI checks pass. Keep CI path filters and `render.yaml` build filters aligned; tests/docs alone should not trigger builds.
- Use `.env.example` for placeholders only. Java does not automatically load `.env`; IDE/Tomcat and Render must receive environment variables.
- Follow `docs/QUY_UOC_PHAT_TRIEN.md` and `docs/API_BASE.md`. Packages are `common`, `auth`, and `business/<module>/{controller,dto/request,dto/response,entity,repository,service}`. Config classes live in `common/config`; do not reintroduce the old top-level config/web/identity layout.
- Add Vietnamese comments/Javadoc for flows, service methods and transaction boundaries. Every public API has `@Operation`; request/response fields have `@Schema`. Add all message keys to both vi/en bundles; use `BusinessException(ErrorCode, args)` and the shared response factory.
- Bootstrap/migrations run only at application startup when explicitly enabled, never in Maven packaging. Preserve migration checksums, advisory locks, idempotent seed and existing admin passwords. Runtime initialization for the requested admin/catalog foundation is authorized; routine verification uses isolated PostgreSQL, not production.
- Use Spring Security/Nimbus JWT and BCrypt. Never store browser access tokens in localStorage, expose password hashes in DTOs, disable cookie CSRF protection, or trust client audit/role/tenant fields. `auth` owns account credentials and authorization.
- Current foundation/infrastructure/schema/auth work is committed under the configured hieuv526034 identity. Future task ownership is in `docs/PHAN_CONG.md`; do not infer completed contributions from that plan or invent commit authors.
- Use the exact member username/email pairs supplied on 2026-10-22 in the member table of `docs/PHAN_CONG.md`: anhhoang104, BangPhamIT, hiencoi250404-design, hieuv526034. Do not derive emails or GitHub usernames from legacy branch labels or rewrite historical commit authors.
- Branches use `<member>/<task>` as listed in `docs/PHAN_CONG.md`, never `codex/`. Work on the assigned member branch and merge through a passing PR into `main`; do not commit application changes directly to `main`.
- Viết tiêu đề và nội dung commit bằng tiếng Việt có dấu, kể cả merge commit. Tiêu đề nêu rõ hành động và phần bị ảnh hưởng; nội dung giải thích thay đổi, lý do và kết quả kiểm tra thực tế, nêu giới hạn nếu có. Giữ nguyên tên kỹ thuật, mã lỗi và định danh trong code; tránh thông điệp chung chung như `update` hoặc `fix`. Tiêu đề/mô tả PR cũng dùng tiếng Việt theo mẫu trong `CONTRIBUTING.md`. Áp dụng cho commit mới, không viết lại lịch sử đã chia sẻ chỉ để đổi ngôn ngữ.
- Use uppercase `DTO` in Java class names such as `BaseDTO`, never `Dto`. Keep package names lowercase `dto`; descriptive request/response names such as `LoginRequest` and `UserResponse` remain valid.
- Use `Instant` for Java business/audit timestamps and PostgreSQL `TIMESTAMPTZ`. Convert JDBC `Timestamp` only at the database boundary; never expose it or `Date` in entities, DTOs or service contracts.
- Run `npm ci`, `npm run format` and `npm run format:check` for development formatting. Use four spaces, separate statements/annotations onto their own lines, and blank lines between fields, methods and logical blocks. Formatting tooling is development-only and must not add Node/test steps to production Docker builds. Never reformat applied SQL migrations.
- Application schema defaults to `vietroute` inside Neon database `neondb` and is configured only by `VIETROUTE_DB_SCHEMA` (fallback `db.schema` in database.properties). Never hardcode a schema prefix in runtime DAO SQL or entity annotations. Every borrowed connection sets a validated search_path to the configured schema with pg_temp last, without public/$user fallback. `@JdbcTable`/`@JdbcIndex` declare table/PK/index metadata using the configured connection schema. Keep V001–V003 byte-for-byte unchanged; LegacyMigrationSql adapts only V002/V003 in memory with raw-file checksums preserved. New migrations use the configured search_path. Changing existing schema data requires an offline rename; startup must reject an unexpected/multiple history instead of seeding a second application.
- Permissions use resource-specific READ/CREATE/UPDATE/DELETE/ASSIGN actions; never grant a global READ/WRITE/DELETE bypass. CATALOG_WRITE and ACCESS_WRITE remain compatibility codes with documented limited scope. Enforce the action at service methods, validate scope/audit/version, and keep permission keys in both locales.
- Use explicit imports at the top of Java files, without wildcard imports or fully qualified class names in executable code. Separate classes when library type names collide. Prefer method references over lambdas that only forward an unchanged invocation; keep meaningful callbacks readable.
- Business/auth APIs extend `BaseController` and use its execute/try-catch flow. `ApiExceptionMapper` is shared with `GlobalExceptionHandler` for pre-controller MVC errors. Preserve correct HTTP status, locale, traceId and sanitized errors; explain flows in Vietnamese and follow `docs/LUONG_XU_LY_BASE.md`.
