# Project conventions

- Stack: Java 17+, Spring MVC 6, Thymeleaf, plain JDBC, PostgreSQL, WAR on Tomcat 10.1. Do not introduce Spring Boot or an ORM without a task requiring it.
- Production database is the user's Neon PostgreSQL `neondb`. Credentials are in the ignored local `.env` and Render environment variables. Do not print, commit, or bake credentials into images.
- Use PostgreSQL SQL syntax for all new schema/DAO work. Do not run schema changes, seed data, cleanup, or write tests against production as part of routine build verification.
- Put Java tests in `src/test/java` and test fixtures in `src/test/resources`. Production Docker builds copy only `src/main` and use `-Pproduction`, which skips both test compilation and execution. Keep tests and test dependencies out of the production WAR/image.
- GitHub Actions validates the production Docker container. Render builds from `Dockerfile` and deploys `main` only after CI checks pass. Keep CI path filters and `render.yaml` build filters aligned; tests/docs alone should not trigger builds.
- Use `.env.example` for placeholders only. Java does not automatically load `.env`; IDE/Tomcat and Render must receive environment variables.
- Follow `docs/QUY_UOC_PHAT_TRIEN.md` and `docs/API_BASE.md`. Packages are `common`, `auth`, and `business/<module>/{controller,dto/request,dto/response,entity,repository,service}`. Config classes live in `common/config`; do not reintroduce the old top-level config/web/identity layout.
- Add Vietnamese comments/Javadoc for flows, service methods and transaction boundaries. Every public API has `@Operation`; request/response fields have `@Schema`. Add all message keys to both vi/en bundles; use `BusinessException(ErrorCode, args)` and the shared response factory.
- Bootstrap/migrations run only at application startup when explicitly enabled, never in Maven packaging. Preserve migration checksums, advisory locks, idempotent seed and existing admin passwords. Runtime initialization for the requested admin/catalog foundation is authorized; routine verification uses isolated PostgreSQL, not production.
- Use Spring Security/Nimbus JWT and BCrypt. Never store browser access tokens in localStorage, expose password hashes in DTOs, disable cookie CSRF protection, or trust client audit/role/tenant fields. `auth` owns account credentials and authorization.
- Current foundation/infrastructure/schema/auth work is committed under the configured hieuv526034 identity. Future task ownership is in `docs/PHAN_CONG.md`; do not infer completed contributions from that plan or invent commit authors.
