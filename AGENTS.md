# VietRoute — chỉ dẫn dùng chung cho AI

## Bắt đầu mỗi phiên làm việc

1. Đọc file này, [AI và bàn giao](docs/06-ai-va-ban-giao/AI_VA_BAN_GIAO.md), [tiến độ](docs/05-ke-hoach/TIEN_DO_VA_KE_HOACH_NHOM.md) và [phân công](docs/05-ke-hoach/PHAN_CONG.md). Theo [mục lục](docs/README.md) để đọc thêm đúng chuyên đề trước khi sửa phần đó.
2. Kiểm `git status --short --branch`, commit gần nhất và code/PR liên quan. Nêu ngắn gọn mã việc, phần đã có/còn thiếu, nhánh/người thực hiện và cách kiểm; tiếp tục công việc đã được người dùng cho phép. Giữ nguyên thay đổi có sẵn của người khác.
3. Quy tắc repo nằm ở đây; trạng thái/bằng chứng nằm ở tiến độ/PR; quyết định dài hạn nằm trong tài liệu chuyên đề. File dành riêng cho từng công cụ chỉ dẫn về nguồn này, không sao chép một bộ quy tắc khác. Không coi chat, memory cá nhân hoặc kế hoạch là bằng chứng chức năng đã hoàn thành.
4. Chốt source bằng formatter đã khóa: `npm ci`, `npm run format`, `npm run format:check`; chạy `npm run check:rules`, `npm run check:docs` và kiểm thử phù hợp thay đổi. Stage file mới trước kiểm repository vì checker chỉ đọc file được Git theo dõi. Không tự sửa rule/formatter để làm check xanh.
5. Trước khi dừng, cập nhật tài liệu/PR theo mẫu bàn giao trong quy trình AI: đã làm, còn dở, quyết định và lý do, test đã chạy/chưa chạy, giới hạn và bước tiếp theo. Không ghi secret hoặc quyết định chỉ trong memory cá nhân. Chỉ ghi Đã có trên main khi có merge thật.

Docs: gốc `docs/` chỉ giữ README với 5 bước đọc và link các cụm 01–06/99. Đặt chuyên đề vào cụm phù hợp, ưu tiên sửa/gộp nội dung đang có; không thêm file Markdown rời hoặc bản sao quy tắc/trạng thái. Khi chuyển/gộp tài liệu phải cập nhật mọi link/prompt/checker; chạy check:docs để giữ cấu trúc này.

## Project conventions

- Stack: Java 17+, Spring MVC 6, Thymeleaf, plain JDBC, PostgreSQL, WAR on Tomcat 10.1. Do not introduce Spring Boot or an ORM without a task requiring it.
- Production database is the user's Neon PostgreSQL `neondb`. Credentials are in the ignored local `.env` and Render environment variables. Do not print, commit, or bake credentials into images.
- Use PostgreSQL SQL syntax for all new schema/DAO work. Do not run schema changes, seed data, cleanup, or write tests against production as part of routine build verification.
- Put Java tests in `src/test/java` and test fixtures in `src/test/resources`. Production Docker builds copy only `src/main` and use `-Pproduction`, which skips both test compilation and execution. Keep tests and test dependencies out of the production WAR/image.
- GitHub Actions validates the production Docker container. Render builds from `Dockerfile` and deploys `main` only after CI checks pass. Keep CI path filters and `render.yaml` build filters aligned; tests/docs alone should not trigger builds.
- Use `.env.example` for placeholders only. WAR/Tomcat and Render receive environment variables. The `local` development launcher explicitly enables the ignored local env file through ConfigurationEnvironment; OS/IDE values take precedence. Tests/builds never implicitly read the local file.
- Follow `docs/02-phat-trien/QUY_UOC_PHAT_TRIEN.md` and `docs/02-phat-trien/API_BASE.md`. Packages are `common`, `auth`, and `business/<module>/{controller,dto/request,dto/response,entity,repository,service}`. Config classes live in responsibility subpackages of `common/config` (application/database/integration/traffic/monitoring/web); only RootConfig/WebApplicationInitializer stay at its root; do not reintroduce the old top-level config/web/identity layout.
- Add Vietnamese comments/Javadoc for flows, service methods and transaction boundaries. Every public API has `@Operation`; request/response fields have `@Schema`. Add all message keys to both vi/en bundles; use `BusinessException(ErrorCode, args)` and the shared response factory.
- Bootstrap/migrations run only at application startup when explicitly enabled, never in Maven packaging. Preserve migration checksums, advisory locks, idempotent seed and existing admin passwords. Runtime initialization for the requested admin/catalog foundation is authorized; routine verification uses isolated PostgreSQL, not production.
- Use Spring Security/Nimbus JWT and BCrypt. Never store browser access tokens in localStorage, expose password hashes in DTOs, disable cookie CSRF protection, or trust client audit/role/tenant fields. `auth` owns account credentials and authorization.
- WAR dùng root/servlet context riêng; giữ `@EnableMethodSecurity` ở cả `SecurityConfig` và `WebConfig` để bảo vệ service lẫn controller/page. Khi sửa kiểm quyền, có regression dựng hai context như production và kiểm người thiếu quyền nhập URL trực tiếp, không chỉ kiểm menu/context gộp.
- Current foundation/infrastructure/schema/auth work is committed under the configured hieuv526034 identity. Future task ownership is in `docs/05-ke-hoach/PHAN_CONG.md`; do not infer completed contributions from that plan or invent commit authors.
- Use the exact member username/email pairs supplied on 2026-10-22 in the member table of `docs/05-ke-hoach/PHAN_CONG.md`: anhhoang104, BangPhamIT, hiencoi250404-design, hieuv526034. Do not derive emails or GitHub usernames from legacy branch labels or rewrite historical commit authors.
- Branches use `<member>/<task>` as listed in `docs/05-ke-hoach/PHAN_CONG.md`, never `codex/`. Work on the assigned member branch and merge through a passing PR into `main`; do not commit application changes directly to `main`.
- Viết tiêu đề và nội dung commit bằng tiếng Việt có dấu, kể cả merge commit. Tiêu đề nêu rõ hành động và phần bị ảnh hưởng; nội dung giải thích thay đổi, lý do và kết quả kiểm tra thực tế, nêu giới hạn nếu có. Giữ nguyên tên kỹ thuật, mã lỗi và định danh trong code; tránh thông điệp chung chung như `update` hoặc `fix`. Tiêu đề/mô tả PR cũng dùng tiếng Việt theo mẫu trong `CONTRIBUTING.md`. Áp dụng cho commit mới, không viết lại lịch sử đã chia sẻ chỉ để đổi ngôn ngữ.
- Use uppercase `DTO` in Java class names such as `BaseDTO`, never `Dto`. Keep package names lowercase `dto`; descriptive request/response names such as `LoginRequest` and `UserResponse` remain valid.
- Use `Instant` for Java business/audit timestamps and PostgreSQL `TIMESTAMPTZ`. Convert JDBC `Timestamp` only at the database boundary; never expose it or `Date` in entities, DTOs or service contracts.
- Audit actor hệ thống dùng `ApplicationConstants.SystemActor.ID` (0, username system), không NULL. V006 lấp riêng audit NULL, giữ actor/timestamp/version/hash cũ, thêm DEFAULT/NOT NULL/FK. System không đăng nhập, nhận role hoặc JWT; thao tác người dùng ghi principal, worker ghi system. Đọc `docs/02-phat-trien/AUDIT_VA_SYSTEM.md`, giữ V001–V005 nguyên vẹn và không chạy backfill trên production để kiểm build.
- Run `npm ci`, `npm run format` and `npm run format:check` for development formatting. Use four spaces, separate statements/annotations onto their own lines, and blank lines between fields, methods and logical blocks. Formatting tooling is development-only and must not add Node/test steps to production Docker builds. Never reformat applied SQL migrations.
- IntelliJ dùng `.idea/codeStyles/Project.xml` và `.editorconfig` theo `docs/01-bat-dau/FORMAT_INTELLIJ.md`; chỉ chia sẻ codeStyles, không workspace/env cá nhân. Mọi lượt sửa source phải tự chạy format và format:check trước commit/bàn giao; formatter không thay thế comment tiếng Việt, DTO/Instant hoặc review logic. Người mới bắt đầu tại `docs/README.md`; tài liệu mới phải có link trong nhóm phù hợp của mục lục này.
- Khi tiếp tục phiên mới hoặc chuyển máy, đọc `docs/06-ai-va-ban-giao/AI_VA_BAN_GIAO.md`, mục lục docs, tiến độ và tài liệu của task; kiểm `git status`/nhánh/commit và code thực tế trước khi sửa. Lưu quyết định dùng lại, việc còn dở và bằng chứng vào docs/PR; không dựa riêng vào lịch sử chat, `.tools/`, process localhost hoặc file chưa push. Sau task cập nhật nguồn tài liệu chính/tiến độ và link mục lục, không nhân bản quy tắc hoặc ghi secret vào phần bàn giao.
- Application schema defaults to `vietroute` inside Neon database `neondb` and is configured only by `VIETROUTE_DB_SCHEMA` (fallback `db.schema` in database.properties). Never hardcode a schema prefix in runtime DAO SQL or entity annotations. Every borrowed connection sets a validated search_path to the configured schema with pg_temp last, without public/$user fallback. `@JdbcTable`/`@JdbcIndex` declare table/PK/index metadata using the configured connection schema. Keep V001–V003 byte-for-byte unchanged; LegacyMigrationSql adapts only V002/V003 in memory with raw-file checksums preserved. New migrations use the configured search_path. Changing existing schema data requires an offline rename; startup must reject an unexpected/multiple history instead of seeding a second application.
- Role is the permission group; do not add a duplicate group layer. Startup validates declared function/action/endpoint definitions and syncs their registry plus ADMIN grants only when enabled; never auto-grant ordinary roles or read DB public flags to bypass WebRoutePolicy/service guards. See `docs/02-phat-trien/SCHEMA_VA_PHAN_QUYEN.md`.
- Permissions use resource-specific VIEW/READ/CREATE/UPDATE/DELETE/ASSIGN actions; never grant a global READ/WRITE/DELETE bypass. CATALOG_WRITE and ACCESS_WRITE remain compatibility codes with documented limited scope. Enforce the action at service methods, validate scope/audit/version, and keep permission keys in both locales.
- Use explicit imports at the top of Java files, without wildcard imports or fully qualified class names in executable code. Separate classes when library type names collide. Prefer method references over lambdas that only forward an unchanged invocation; keep meaningful callbacks readable.
- Business/auth APIs return `ApiResult<T>`, extend `BaseController` and use its execute/try-catch flow. The HTTP body remains `ApiResponse<T>`. `ApiExceptionMapper` is shared with `GlobalExceptionHandler` for pre-controller MVC errors. Preserve correct HTTP status, locale, traceId and sanitized errors; explain flows in Vietnamese and follow `docs/02-phat-trien/LUONG_XU_LY_BASE.md`.
- Public images use `common/media/{controller,service,repository,entity,dto,storage,validation}` with the Cloudinary `MediaStorage` adapter. Reuse MediaService; do not create business/media controllers or a second upload implementation. Validate actual JPEG/PNG bytes and pixel limits, preserve permission/owner checks and durable cleanup; never accept client public IDs, remote upload URLs or credentials. Private identity documents require a separate design. Read `docs/01-bat-dau/CHAY_LOCAL_VA_CLOUDINARY.md` before linking media to business entities.
- IntelliJ Run/Debug uses the `local` Maven profile and `src/dev/java` launcher. Keep launcher/Tomcat embedded dependencies out of production WAR/images; Docker continues copying only `src/main`. Never put secrets in the shared `.run` configuration.
- Java environment keys, route/matcher strings, validation regex and custom HTTP names live in `ApplicationConstants` (`Env`, `Routes`, `Regex`, `Http`); use typed `ConfigValues` and standard `HttpHeaders`. `WebRoutePolicy` owns public/JWT/quota route classification. Keep external environment/API contracts aligned; adding a route constant never grants permission automatically.
- Keep `common.web` organized into `controller`, `response`, `filter`, `locale`, `advice`, `openapi`, `routing`. System status belongs to `common.monitoring/{controller,dto/response,service}`. Do not add flat web services/DTOs or compatibility duplicates; update imports and follow `docs/02-phat-trien/CONSTANTS_VA_CAU_TRUC_WEB.md`.
- Current phase does not require Kafka/Redis. Preserve optional legacy adapters without enabling them; memory quota is per node. Follow `docs/01-bat-dau/TONG_QUAN_HE_THONG.md` and `docs/04-van-hanh/GIAM_SAT_VA_VAN_HANH.md`. Keep job/mail classes in responsibility subpackages and wiring in DatabaseConfig/IntegrationConfig/TrafficConfig/MonitoringConfig. Metrics labels must remain bounded, token scrape must not access DB/JWT, and database probing stays opt-in. Never claim external alerts/backup are live solely because config templates exist.
- Trang nhiều nhóm chức năng dùng tab; form thêm/sửa/gán và upload dùng modal theo `docs/03-giao-dien/QUY_UOC_UI.md`. Tái sử dụng `workspace.js`, giữ tab bàn phím/ARIA, focus modal và lỗi ngay trong modal; không tự đóng hoặc gửi lại mutation khi lỗi, không đóng lúc request đang gửi. Không lưu mật khẩu/token trong tab/storage hoặc thay kiểm quyền backend bằng UI.
- Bảng/phân trang/validation UI theo `docs/03-giao-dien/QUY_UOC_UI.md`: dùng fragment pagination + table.js/forms.js, phân trang server, cột thao tác 96px/icon có aria-label, toolbar/footer modal bên phải. Lỗi 401 có link đăng nhập lại và giữ bản nháp; Home/login chọn trang từ principal, không thay kiểm quyền.
- Nhật ký API nằm trong `common.monitoring`, chỉ ADMIN + SYSTEM_READ. Theo `docs/04-van-hanh/NHAT_KY_API_VA_DEBUG.md`: projection DTO/field tường minh, field mới mặc định bỏ; không raw body/response/header/cookie/PII/secret. Ngoại lệ metadata theo yêu cầu 24/10: request_user_id từ JWT/password đã xác minh, username join theo ID chỉ ADMIN + SYSTEM_READ; không tin header/body user ID, không backfill log cũ hoặc đưa email vào projection. Theo yêu cầu mới, lịch sử ghi trực tiếp PostgreSQL, không cache/queue lịch sử trong RAM; retention mặc định 7 ngày, mục tiêu 10000 dòng, cleanup theo lô có advisory lock. Pool riêng tối đa 1 connection/node và timeout/backoff để lỗi log không làm lỗi nghiệp vụ; công bố missed-write counter, không hứa đủ mọi trace khi DB/slot lỗi. Giữ V001–V004 nguyên vẹn, migration mới V005 dùng schema cấu hình. Export cURL/Postman điền URL thực từ origin + context ứng dụng; token/body bị che vẫn placeholder theo lựa chọn chủ dự án, không đọc cookie auth hoặc tự replay mutation; không coi journal là audit bất biến/API gateway.

- Role/Permission are stable JSON string value objects backed by DB registry; values() is bootstrap constants only. Custom permission codes must never start ROLE_; ACCESS_CREATE/UPDATE/DELETE manage registry/policies, ACCESS_ASSIGN manages mappings only. Additional menu/endpoint policies never weaken mandatory backend guards; preserve the ADMIN recovery path. Activity presence/buckets live directly in PostgreSQL with bounded retention/capacity, no RAM history queue; read only as ADMIN + SYSTEM_READ and disclose missed writes/window semantics per monitoring docs.

- Email lifecycle uses opt-in AUTH_SELF_SERVICE + configured mail/worker; public registration only grants CUSTOMER pending email activation. Keep 5 failures/15-minute lock (no forced reset), single-use expiring codes, encrypted auth outbox, generic request responses, CSRF/quota, and current + two previous password exclusion. Existing admin/legacy accounts stay active without forced activation. V011 appends schema; never alter V001–V010 or test writes on Neon. See API_BASE.md for runtime/provider limitations.

- AccessFunction annotations declare the HTTP function/ANY-or-ALL permission guard and inventory; use common.constant.AccessConstants.Groups/Permissions for compile-time codes, shared with Permission. Actual DB authorities and AccessRules service guards remain mandatory. Header/buttons use the same capabilities and endpoint policies; VIEW is independent from READ. ACCESS permissions may be delegated within the actor's existing authority set, including checks against reactivating stronger roles/permissions; ADMIN/system/last-admin protections remain. ADMIN registry is immutable. Other roles may be soft-deleted only without user/policy references, clearing permission mappings atomically; preserve tombstones across bootstrap. Profile/avatar are self-service, use common MediaService, own READY images/version and block deletion while referenced. See SCHEMA_VA_PHAN_QUYEN/API_BASE/QUY_UOC_UI for FOUNDATION05 contracts and the ACCESS03 implementation. V013 adds VIEW: drain all older nodes before upgrading; never claim zero-downtime mixed V012/V013 compatibility.
